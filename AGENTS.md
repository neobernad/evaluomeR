This file gives AI agents and new contributors the orientation needed to work
effectively in this repository.

## Package Overview

**evaluomeR** (v1.8.1) is a Bioconductor R package that evaluates the
reliability of bioinformatics metrics by analysing the stability and goodness
of classifications produced by those metrics. The three core analyses are:

- **Correlation** — Pearson correlation matrix across metrics
- **Stability** — Bootstrap Jaccard stability indices over a range of k
- **Quality** — Silhouette and Calinski-Harabasz quality indices over a range of k

An advanced pipeline called **ATSC** (Automated Trimmed & Sparse Clustering)
combines all three analyses with RSKC (Robust Sparse k-Means Clustering) to
automatically select the optimal number of clusters and down-weight irrelevant
metrics.

### Install

```r
# Bioconductor (stable)
BiocManager::install("evaluomeR")

# GitHub (development)
devtools::install_github("neobernad/evaluomeR")
```

- Requires R >= 3.6
- License: GPL-3
- Bug reports: https://github.com/neobernad/evaluomeR/issues
- Docs site: https://neobernad.github.io/evaluomeR/

## Input Data Contract

### Expected input shape

All analysis functions accept either a `data.frame` or a `SummarizedExperiment`.

```
           Description  Metric_A  Metric_B  Metric_C ...
row 1      "Sample_1"   0.82      1.14      0.67
row 2      "Sample_2"   0.91      0.98      0.74
...
```

- The **first column** must be named `Description` and contain instance/sample IDs.
- All remaining columns are numeric metric measurements.
- Helper `createSE()` in `R/helpers.R` wraps a data frame into a `SummarizedExperiment`.

### Bundled datasets

| Dataset | Description |
|---------|-------------|
| `rnaMetrics` | RNA quality metrics (RIN, DegFact) for 16 aliquots — simplest test dataset |
| `ontMetrics` | 19 structural ontology metrics (OBO Foundry + AgroPortal) |
| `bioMetrics` | Biological pathway metrics (reachability, efficiency) |
| `ontMetricsOBO` | Structural ontology metrics on the OBO Foundry corpus |
| `nci60_k8` | NCI-60 cancer cell lines (61 samples, many gene metrics) — used by interactive demo |
| `nci60_k10` | NCI-60 metrics, k=10 partition |
| `golub` | Golub leukemia gene expression (72 samples, AML / B-ALL / T-ALL) — used by interactive demo |
| `breastCancer` | Breast cancer gene expression metrics |

Load any with `data("<name>")`. All `.RData` files are in `data/`, documented in `R/data.R`.

## Supported Clustering Backend Interfaces (CBIs)

Defined in `pkg.env$cbi` inside `R/helpers.R`:

```
"kmeans"    "clara"    "clara_pam"    "hclust"    "pamk"    "pamk_pam"    "rskc"
```

Pass as the `cbi` argument to `quality()`, `qualityRange()`, `ATSC()`, etc.
Default is `"kmeans"` for most functions and `"clara"` for ATSC.

## Running Tests

Tests use **testthat** (edition 3) and live in `tests/testthat/`, one file per
area. `R CMD check` runs them through `tests/testthat.R`; the suite takes about
under 10 s. From the repo root with the package installed:

```r
devtools::test()                                         # whole suite
testthat::test_file("tests/testthat/test-stability.R")   # one area
```

Tests use small bundled data (`rnaMetrics`, `ontMetrics`, `golub`), low `bs`
and fixed seeds, and compare against reference values from the current code.
If a reference value changes, the clustering or bootstrap output changed: only
update it when that change is intended. Prefer real data over mocks; mock
(`local_mocked_bindings()`) only for machinery such as the parallel cluster.

`tests/benchmarks/` holds timing scripts (`*_parallel.R`, `testL1_clustering.R`,
`testPCA.R`, `testCH_index.R`). They have no assertions, take ~20 min, and are
excluded from the package build. Run them with `Rscript tests/benchmarks/<f>.R`.

## Demo Data Export (`tools/`)

Precomputes evaluomeR analyses to JSON for the static UI. **Do not run
bootstrap in the browser** — export via R inside Docker.

### Quick start (recommended)

```bash
# From repo root — builds image if needed, installs evaluomeR, exports both JSONs
docker-compose run --rm evaluomeR bash tools/docker-export.sh
```

Expected runtime: **~30–50 min** with `all_metrics=TRUE`, bs=100 (both datasets),
plus first-time image build (10–20 min). See `tools/DOCKER.md` for more Docker usage.

Outputs:

- `ui/src/data/nci60.json`
- `ui/src/data/golub.json`

### What the export script does

`tools/export-demo-data.R` calls `run_export()` for each dataset:

1. `stabilityRange(..., all_metrics=TRUE, bs=100, seed=13606)`
2. `qualityRange(..., all_metrics=TRUE)` (silhouette)
3. `getOptimalKValue()` → optimal k
4. k-means cluster labels per k (full metric matrix)
5. ARI vs. ground-truth labels per k
6. PCA coordinates (`prcomp`, scaled, PC1/PC2) for the scatter plot
7. Writes only the fields the UI reads; the shape is `DemoData` in
   `ui/src/types/demo.ts`. Add a field there and in the export together.

Parameters match the use-case notebooks: **seed = 13606**, **bs = 100**,
**all_metrics = TRUE** (single merged index, not per-metric).

## Coding Conventions

- **Documentation**: all exported functions use roxygen2 (`@param`, `@return`,
  `@examples`, `@export`). Run `devtools::document()` to regenerate `man/` and
  `NAMESPACE`. Never edit `.Rd` files or `NAMESPACE` by hand.
- **Function naming**: exported functions use camelCase (e.g. `stabilityRange`,
  `getOptimalKValue`). Internal helpers use lower_snake or camelCase
  inconsistently — follow the style of the file you are editing.
- **I/O pattern**: functions accept either a plain `data.frame` or a
  `SummarizedExperiment`; they normalise internally and always return a
  `SummarizedExperiment` (or `MultiAssayExperiment` / named list of SEs for
  `*Range` / `*Set` variants).
- **Package-scoped state**: mutable package state lives in `pkg.env` (a
  `new.env()`), defined in `R/helpers.R`. Avoid introducing global variables
  outside this environment.
- **Parallel execution**: `quality*`, `stability*`, `getRSKCAlpha` and `ATSC`
  accept `numCores` and use `parallel::makeCluster` + `parLapply`. Caveats:
  `quality*` / `stability*` parallelise **across metrics only**, so with
  `all_metrics=TRUE` (one merged metric) there is no speedup. `ATSC` hard-codes
  `numCores=1` for its internal stability/quality calls (`R/atsc.R`); only its
  `getRSKCAlpha` step uses the caller's `numCores`.
- **Seed handling**: a default seed (`13606`) is stored in `pkg.env$seed`.
  Functions accept an optional `seed` argument to override it for
  reproducibility.
- **Adding a new CBI**: register the name in `pkg.env$cbi` (`R/helpers.R`),
  implement a CBI function in `R/internalClusterboot.R`, and wire it into the
  dispatch logic in `R/internalFunctions.R`.

## Agent Workflow

### Branching (required)

Unless told otherwise, start every new piece of work on a fresh branch cut
from an up-to-date `develop`:

```bash
git checkout develop
git pull origin develop
git checkout -b feature/<short-description>   # or fix/<...>
```

Never commit new work directly to `develop` or `master`. Open PRs back into
`develop`; `master` receives releases only.

### Ponytail (optional, local install)

[Ponytail](https://github.com/DietrichGebert/ponytail) lazy-senior-dev mode is
**not committed to this repo** — agent tooling is a per-developer choice. To
enable it in Cursor locally:

```bash
mkdir -p .cursor/rules
curl -fsSL https://raw.githubusercontent.com/DietrichGebert/ponytail/main/.cursor/rules/ponytail.mdc \
  -o .cursor/rules/ponytail.mdc
```

Default intensity: **full**. Say `stop ponytail` / `normal mode` to turn it off
for a session. `.cursor/` is gitignored.

### Area-specific tests (required after code changes)

See [Running Tests](#running-tests). After editing package code, run the
test files for the area you changed (or the whole suite, under 10 s):

```r
testthat::test_file("tests/testthat/<file>.R")
```

**Coverage gap:** no test calls `globalMetric`,
`annotateClustersByMetric` or `getMetricRangeByCluster`. When touching them,
verify manually against a bundled dataset (e.g. `rnaMetrics`).

R/metricsAnalysis.R" (file was split). Run `devtools::document()` to regenerate.

For ATSC, RSKC, PCA, quality-index or parallel changes, also run the matching
script in `tests/benchmarks/` by hand.

When a change spans multiple areas, run every matching test file before claiming
the work is done.
